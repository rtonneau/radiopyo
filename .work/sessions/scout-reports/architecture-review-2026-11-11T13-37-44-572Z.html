radiopyo scout (2026-11-11): efficiency and JupyterLab usage

Direction: (1) efficiency, (2) user experience, restricted to use from a JupyterLab notebook. Base: main @ 5cc8895.

Measurements (Windows, Anaconda Python 3.13, this machine)

  • UnitCell.from_toml(LABARBE_CONFIG_FILE): 9.5 s first load, 3.3 s warm. 9.4 s of 9.5 s in Lark Earley parsing: 310 parses at ~30 ms each (218 from reaction_key during the include merge, the rest in the reaction builders).
  • Labarbe: 30 species, 85 k-reactions, stoichiometry 273 non-zeros out of 2550. derive 108 µs/call, jacobian 349 µs/call.
  • uc.run((1e-7, 10)): 1.2 s, 4273 nfev, 147 njev. Reconstructing the rates: 17 ms.
  • Pulsed chunked run (1e4 Gy/s peak, 10 ms period, 10 µs ON, 10 Gy, 200 chunks): 7.5 s. _k_relaxation_terms takes 2.85 s (38%); dataclasses.replace → _lock_arrays is called 23,640 times; np.delete 22,872 times.
  • The bundled notebook flow (pure water, pulsed beam, chunked run) prints 18 INFO lines prefixed with a timestamp and radiopyo::INFO::.
  • repr(uc) and repr(res) are <... object at 0x...>; repr(uc.env) is a raw dataclass dump.

Candidates

1. fast-config-loading (Strong, High)

Every reaction string goes through an ambiguous Earley grammar (lark.Lark(grammar), default parser), and each one is parsed at least twice (merge key, then builder). Fix: memoize the parse per string (copy on return), reuse the parsed reaction from the merge, and consider LALR with a contextual lexer if the grammar can be disambiguated. Files: parser/reaction_parser.py, parser/utils.py, simulation/environment_build.py.

2. overshoot-path-precompute (Strong)

When a species is below 0, every derive/jacobian call rebuilds per-species sub-matrices (dataclasses.replace, which re-locks arrays) and loops over np.delete. Fix: precompute the per-species reaction subsets once, when SimMatrices is built, and vectorise depletion_switch_derivatives and mass_action_derivatives. Files: simulation/ode_functions_solver.py, utils/sim_types.py, simulation/environment_build.py.

3. rhs-call-overhead (Worth exploring)

derive and jacobian cost is NumPy call overhead (np.ones, concatenate, flatnonzero, broadcast_to, to_full_molar allocation), not arithmetic. Fix: precompute index arrays and constant buffers in SimMatrices, use sparse stoichiometry (11% dense), and possibly add an opt-in compiled backend (numba). Files: simulation/ode_functions_solver.py, utils/sim_types.py.

4. chunked-run-scaling (Worth exploring)

Each chunk has a fixed cost of about 37 ms. ODEResult.append_sol copies the whole history on every chunk (np.append/hstack, so the cost is quadratic in the number of chunks). dose_rates loops in Python over every time point, and every ODEResult deep-copies env, beam and matrices. A conventional pulsed linac (about 1e4 pulses) means 2e4 chunks. Files: simulation/ode_result.py, simulation/unit_cell.py, simulation/ode_functions_solver.py, physics/beam.py.

5. notebook-rich-display (Strong)

The main objects have no useful repr in Jupyter. Fix: add __repr__ and _repr_html_ summaries for UnitCell, ODEResult, SimEnv and the beams. Files: simulation/unit_cell.py, simulation/ode_result.py, simulation/environment_build.py, physics/beam.py.

6. notebook-quiet-logging (Strong)

INFO output is verbose and goes to stdout in every cell. The tqdm detection is hand-written (get_ipython), and a plain run() shows no progress. Fix: a quieter default or a concise format in notebooks, a context manager or flag to silence a run, and tqdm.auto. Files: utils/default_log_config.toml, utils/logging.py, simulation/unit_cell.py.

7. notebook-plot-helpers (Worth exploring)

Every notebook re-codes the log-time plot, the pH conversion and the units. No cumulative dose versus time exists on beams or results. Fix: res.plot(...), res.pH, res.dose / beam.dose_at(t), with matplotlib as an optional extra. Files: simulation/ode_result.py, physics/beam.py.

8. simpler-setup-api (Strong)

Traps: the bundled notebook calls from_dose_rate_peak(peak, period, on_time, max_dose), so its 4th positional argument is n_pulse. It only works because 1000 × 1e-3 × 10 = 10 Gy. Other traps: sp.set_initial_cc (mol/L) needs a manual uc.update_env(); results, y0 and atol are in µM; set_beam(LET=None) silently reuses the previous LET; res["o2"] raises KeyError without suggestions. Files: simulation/unit_cell.py, physics/beam.py, chemistry/species.py, simulation/ode_result.py.

9. parameter-sweep-helper (Worth exploring)

The typical notebook task is a sweep (dose rate, O2, LET, pulse structure). Each new UnitCell costs seconds, and ResCollection / SimCollection have no driver that fills them. Fix: uc.copy() and a sweep() that returns a tidy DataFrame or ResCollection, optionally in parallel. Files: simulation/unit_cell.py, simulation/result_collection.py.

10. notebook-example-ci (Worth exploring)

examples/notebook_basic_usage.ipynb is not executed by the tests. It shows the positional-argument trap, the old alias names, and a comment that says reactions_involving returns tuples. Fix: run the notebook in pytest (nbmake or nbclient, short t_span) and refresh it to show the recommended API. Files: examples/notebook_basic_usage.ipynb, tests/.
