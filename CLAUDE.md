This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`radiopyo` is a pure-Python package (no C++, despite the global Geant4-DNA rules — those don't apply here) that simulates water radiolysis and radiobiology chemistry under UHDR/CONV irradiation by solving a system of ODEs with `scipy.integrate.solve_ivp` (LSODA by default). Originally a port of R. Labarbe's MatLab model. The math behind the ODE system is documented in `doc/20230425_RPM_extended_doc.pdf`.

## Architecture

The pipeline is **config file → `SimEnv` → matrices → `derive()` → `ODEResult`**.

1. **Parsing** (`radiopyo/parser/`): `FileParser` subclasses (`toml.py`) produce a `ConfigDict` (TypedDicts in `radiopyo/utils/sim_types.py`; TOML is the only format, the RON parser is gone). `resolve_includes` (`file_parser.py`) recursively loads the `[includes]` files first; the merge (`parser/utils.py`: `combine_config`, `reaction_key`) is one generic function that never builds reaction objects and keys reactions on their species, order-insensitively. Precedence: the including file overrides its includes and a later include overrides an earlier one; a reaction override replaces field by field (only what is written). An include path is relative to the including file (fallback: CWD); only the exact prefix `radiopyo/` maps to `radiopyo/data/` (`PACKAGE_DATA_PATH`). Reaction strings (`"A + B -> 2 C"`, `"2H2O2 -- catalase >> O2 + 2 H2O"`, the enzyme is a plain name in any case) are parsed by Lark grammars in `parser/grammar/` via the shared `RPARSER` singleton into `GenericReaction` dicts (`chemistry/generics.py`).

2. **Chemistry objects** (`radiopyo/chemistry/`): all reactions derive from `BasicReaction` (shared species population `_add_species_from_generic`, `make_hash`, `_index_label`). `KReaction` (plus `Arrhenius`, `CstReaction`) for rate-constant reactions; `BiReaction` subclasses `AcidBase` and `EReaction` own two k-reactions (forward/backward, k set on them); `MichaelisMenten` for enzymatic reactions; `RadiolyticReaction` for G-value production. n·k rule (ADR 0001): for `n A -> B` a *scalar* k is divided by n, polynomial/Arrhenius/equilibrium k are used as given (a warning is logged for n > 1 with such a k). `Arrhenius`: `k = A exp(-Ea·1000/(R T))`, `Ea` in kJ/mol. Species live in `ListSpecies` (deterministic order: order of appearance in the config, never a `set`) and are split into **dynamic** (solved) and **fixed** (`[concentrations.fixed]`) species; `SimSpecies.cc_init` is `None` when there is no initial-concentration polynomial.

3. **Environment** (`simulation/environment_build.py`): `SimEnv.from_dict` builds a `ReactionsList` (table-driven readers `_REACTION_BUILDERS` / `reactions_from_dict`; one `reactions_involving(species, role=, kinds=)` query, the old `*_involving*` names are aliases) whose `__post_init__` assigns **global reaction indices in a fixed order**: acid/base (2 each), equilibrium (2 each), k-reactions, enzymatic, then radiolytic. Results analysis relies on these indices (`get_reaction_by_index`), so keep that ordering when adding reaction types. The temperature has one source of truth, `env.parameters["temperature"]` (degC; `SimEnv.temperature` / `set_temperature`, `UnitCell.T`): fixed species, initial values, k polynomials and `ODEResult` all read it. `build_all_matrices()` returns a frozen `SimMatrices` (`utils/sim_types.py`) made of `KMatrices` (k-reaction indices, stoichiometry, negative-product flags), `GVector` (radiolytic yields and stoichiometry), `EzMatrices` (enzymatic) and `StateLayout` (fixed-species vector, µmol/L ↔ mol/L conversion); the arrays are read-only. `SimEnv.make_hash` is broken (always raises `TypeError`): do not rely on it.

4. **Solver** (`simulation/ode_functions_solver.py`): `derive(t, y, beam, mat)` is the right-hand side. It converts `y` (**µmol/L**, dynamic species) to the full molar state with `mat.state.to_full_molar` (fixed species appended), calls the pure `reaction_rates(t, y_full, mat, beam)` (returns `ReactionRates`: k, radiolytic and enzymatic rates; index gathers and matmuls, no per-reaction loops) and applies the stoichiometry matrices (dy/dt = S·r when every c >= 0; a dynamic species below 0 gets the overshoot relaxation, see below). `ODEResult.reconstruct_reactions` calls the same `reaction_rates`, so the two cannot drift. Rate laws (mass action and Michaelis–Menten) read the clipped concentration max(c, 0), always (ADR 0004; the old positivity flag is gone and raises `TypeError`). Each "negative" product of a k-reaction or enzymatic reaction multiplies the rate once by the smooth depletion switch c⁺/(c⁺+ε), ε = `DEPLETION_LIMIT` (`depletion_switch`, `depletion_switch_derivatives`; ADR 0005; enzymatic flags via `EzMatrices.negative_products`; a negative enzymatic product is subtracted in the stoichiometry). `jacobian(t, y, beam, mat)` is the pure dense analytic Jacobian of `derive`: smooth except at c = 0 (ADR 0005 supersedes the piecewise part of ADR 0003 in `.work/adr/`). Overshoot relaxation (ADR 0007, amends ADR 0004): every other species and rate still read a species with c < 0 as 0 (so its column in the rates is 0), but its own row is continued linearly from c = 0⁺ (dc/dt += J_jj(0⁺)·c, included in the Jacobian), so dy/dt is no longer exactly S·r for such a state and LSODA does not stall at the kink of a stiff radical near 0. The per-species sub-tables of that path (`OvershootTables`, `SimMatrices.overshoot`) and the padded negative-product index (`KMatrices`/`EzMatrices.negative_index`, `pad_slots`) are derived once when the matrices are built (`init=False` fields), never per call; `tests/simulation/test_overshoot_equivalence.py` keeps a frozen copy of the pre-refactor math (rtol 1e-12) and `examples/bench_overshoot_pulsed.py` measures the path (200-chunk pulsed run, config_Labarbe). `derive` is still several times slower on a state with a species below 0. A failed `solve_ivp` raises `SolverFailedError` (`simulation/exceptions.py`) from the `UnitCell` runs, never a truncated result.

5. **Driver** (`simulation/unit_cell.py`): `UnitCell` holds a `SimEnv`, `mat: SimMatrices`, a `BeamCollection` and `GValuesBoscolo`. The solver options of `run` / `prepare_chunked_run` / `prepare_single_pulse` are gathered in the frozen `RunOptions` (`use_jac=True` by default: the Jacobian is passed to LSODA, BDF and Radau only, other methods ignore it); `_raw_run(t_span, options, y0, beam_on)` is a sequence of small steps (`widen_empty_span`, `_solver_kwargs`, `_apply_initial_burst`, `_timed_solve`). A `y0` given by the caller is never modified. Setting a beam with an LET rewrites the G-values of e_aq, OH_r, H_r, H2, H2O2 and H3O_plus (taken equal to e_aq, ADR 0002) from the Boscolo 2020 fit (`utils/g_values.py`, valid LET 0.13–150 keV/µm; with `variable_GValues` a dose-rate factor, `_scale_factor`, is applied without range check) and rebuilds the matrices. On beam ON (and `use_beam=True`), the first `T_ZERO` = 1e-7 s is skipped and the radiolytic yield for that interval is added analytically to `y0` (recorded in `ODEResult.burst_dose_rates`). `prepare_chunked_run()` splits pulsed beams into ON/OFF `SimChunk`s with different max step sizes (cut exactly at the beam transitions: `ParticleBeam.GROWTH_TIME` is gone; a configured beam ON time below `MIN_BEAM_ON_TIME` = 1e-6 s raises `ShortBeamOnError` when the beam is built, ADR 0008; a run-time ON span shorter than that, a *short ON span* such as a last pulse cut by `max_dose` or a pulse clipped by `t_span`, is not integrated: `_short_on_span_step` adds its radiolytic yield analytically, logs a warning and records it in `ODEResult.short_on_spans`, with a step dose rate of 0); each chunk carries a constant `SimChunk.dose_rate` (beam at the chunk midpoint) passed to the solver as a `ConstantDoseRate`, and `ODEResult.step_dose_rates` keeps it for `reconstruct_reactions`. `prepare_single_pulse` builds its chunks the same way before the time of max dose (OFF chunks before it use `max_step_size_trans`). `run()` still reads `beam.at(t)` at every evaluation. `run_till_max_dose` builds on `run`. A missing beam raises `NoBeamDefinedError`.

6. **Beams** (`physics/`): `timer.py` (`Timer`, `MacroTimer` state machines, `TimerState`), `beam.py` (`ConstantBeam`, `SinglePulseBeam`, `PulsedBeam`, `MacroPulsedBeam` and the `BEAM_TYPES` registry; it re-exports the timers and `BeamCollection`) and `beam_collection.py` (`BeamCollection`). One generic `ParticleBeam.make_matrix` walks the timer transitions for every beam type. `beam.at(t).dose_rate()` is what `derive` calls on every evaluation. `from_dict` never mutates its argument. `PulsedBeam.from_dose_rate_peak(peak_dr, period, on_time, n_pulse, max_dose, start_time)`: pass `max_dose=` by keyword (the 4th positional argument is `n_pulse`). `radiopyo/exceptions.py` holds the root `RadioPyoError`; `chemistry`, `physics` and `simulation` each have an `exceptions.py` deriving from it.

7. **Results** (`simulation/ode_result.py`, `units.py`, `result_collection.py`, `persistence.py`): `ODEResult` wraps the scipy solution with the env and matrices so it can recompute per-reaction rates (production/consumption integrals, equilibrium yields, `integrate_species`, `to_pandas`, `species_balance_evolution`). `units.py` holds the unit converters (`O2Convert`, …), `result_collection.py` the `ResCollection`, `persistence.py` the HDF5 layer (`H5Manager`, `SimIdentifier` — a dataclass key serialized into HDF group names, rebuildable from its `repr` via `ast` — and `SimCollection`, lazy on-demand loading of stored `ODEResult`s; uses `h5py`). `simulation/utils.py` is only a facade re-exporting those names, the old import paths keep working. Files written by older versions must keep loading.

Logging: importing `radiopyo` configures the `radiopyo` logger from `utils/default_log_config.toml` (INFO on the console, existing loggers left enabled). Use `logging.getLogger("radiopyo")` and avoid `print` (ruff `T20`).

## Conventions

- Every module follows the same banner layout: shebang, docstring with `Author:` line, then `External imports` / `Internal imports` / `Type checking ONLY imports` / `Expose importable stuffs` (`__all__`) / `Logging` / `FUNCTION DEFINITIONS` / `CLASS DEFINITIONS` sections. Keep it when adding files.
- `import typing as tp`, `from __future__ import annotations`; fully typed signatures (mypy `disallow_untyped_defs`). Code uses `tp.Self`/`tp.Unpack`, hence `requires-python >= 3.11`.
- Species labels use `_minus` / `_plus` suffixes for charge and `_r` for radicals (e.g. `O2_r_minus`, `Fe_plus_plus`, `e_aq`); config concentrations are mol/L.
- Bundled configs: `radiopyo/data/advanced_water_radiolysis.toml` (`PURE_WATER_CONFIG_FILE`), `reactions_biology.toml`, `config_Labarbe.toml` (`LABARBE_CONFIG_FILE`). The README documents every TOML section and beam type.
- `.work/` is the gps (grill-plan-ship) session state and is committed. `origin` is GitHub (`rtonneau/radiopyo`); the original GitLab remote is kept as `gitlab`.
